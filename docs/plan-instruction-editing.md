## First useful result

Choose a gallery image, open **Edit by instruction...**, enter a sentence such
as "make it night", review the source, selected editing checkpoint and exact
output size, and queue one edit with a seed. Save a new child image; keep the
original. Inspect the result beside its source and rerun the same edit.

The first slice uses one source and one instruction, with one image per
pipeline call. The source may have been generated by another checkpoint;
the result belongs to the editing checkpoint. Editing does not promise that
unmentioned pixels stay identical: there is no mask composite. A later edit
of the result is another child, preserving the chain.

The source is a gallery id. External photo/sketch import remains deferred
(`GEN#8`); Load settings from PNG continues to send text chunks only. No batch
detailer, painted mask, outpaint, multi-image edit, automatic model switching,
LoRA support or performance recipe is part of this first slice. Grids, Then
refine and mass instruction editing wait until the basic pass is qualified.

## Where the current app needs a new contract

Today `GenerateRequest.refine` means re-noising a source at a strength, using
the image-to-image sibling of the selected pipeline. An instruction edit
instead calls the editing pipeline itself with a source and instruction.
Treating it as Refine would misstate its schedule and reproduction data.

`DiffusersBackend._reference_supported()` currently asks whether the loaded
call has an `image` argument, which is enough for the existing klein catalogue.
That test cannot distinguish a reference list from an instruction-edit source.
The catch-all `flux` profile likewise cannot supply Kontext-specific defaults
or edit admission. No capability should become available merely because an
unprofiled hand-entered id happens to load a class with `image`.

The catalogue also assumes that its entries can render from a prompt. Extend
that assumption explicitly before adding an editing selection: separate
`text_to_image_supported`, `instruction_edit_supported` and reference/refine/
inpaint capabilities in cold profiles and loaded status. An editor may be
listed for editing without enabling ordinary Generate. Whether Kontext can
technically run without a source does not make that mode part of this release.
Existing catalogue entries retain their current behavior.

Proposed ownership:

| Area | Change to design and validate |
|---|---|
| `launch`, `model_defaults`, `model_info`, `hub_access` | Explicit editor choices, exact profiles, sourced facts and download/access checks; edit-only selections explained in Models. |
| `schemas_generate`, new pure `instruction_edit` module | Frozen versioned spec, validation, working/output geometry and canonical key spelling. Re-export public types through `schemas`. |
| `submission`, `api_generate`, `main` | Source/capability/revision checks, preview and queue admission; new routes included in model-dependent request counting. |
| `backends/loading`, `diffusers_backend` | Editor loading and a separate source-conditioned call branch; explicit loaded capability and cleanup ownership. |
| `storage`, `metadata`, `png_settings`, `grid` | Migration, complete saved identity, source provenance, portable codecs and stable existing run ids. |
| `jobs`, gallery rerun modules, bundles, reindex, CLI | Every producer and reader carries or explicitly refuses the new pass; no silent plain generation. |
| `web` edit dialog, status, facts and image actions | One instruction workflow, preserved composer draft, source lineage and held reasons; classic scripts and existing CSS tokens. |

### CPU persistence and admission slice, 2026-10-27

`GenerateRequest.edit` accepts a strict source/recipe intent or complete stored
replay form. The latter is untrusted input: `instruction_edit_admission` proves
the live source's original decoded RGB digest, basename and dimensions before
binding it. The cold `POST /api/instruction-edit/preview` returns the bound
descriptor and exact geometry with `available: false` and its reason. It does
not select, download, load or queue a model.

The nullable `images.edit` migration and SQL/PNG codecs preserve complete intent,
including unresolved imported sources. Stored results must match the frozen
editor/output geometry and cannot also claim another pass kind. Cell keys bind
the full source proof; absent-edit compaction preserves legacy run ids. Re-render
and More seeds retain the original source. Swap tags and Then refine refuse edits;
an explicit Mass refine child changes pass kind and drops the old edit. PNG
settings and CLI restoration refuse before populating a direct-render workflow.
Retained Finish runs stay inspectable with an unavailable reason.

Source deletion/bin/restore derives availability while preserving the child.
Only full-proof links count for starred-source preservation and bin source use.
Edit history cannot price direct/refine calls; `edit:yes|no` and `stats --by edit`
distinguish it. Reuse keeps the composer draft and Undo intact and stays held
across capability refreshes. The Node VM hold checks do not boot the page or
qualify an actual browser.

Bundle v2 handles whole/selected, plain/password and managed exports while
edit-free archives remain v1. SQL/PNG agreement and downgrade refusal cover fast
paths too. Import/reindex use full RGB proof and complete id maps; missing,
forged, cyclic or omitted links retain unresolved intent. Reindex dry runs stay
nonwriting; `unresolved_edits` counts recovery without a proven local source.

Public backend, job admission/retained-worker, direct model load and fake guards
stay closed even for copied requests. The exact cold Kontext profile does not
inherit ordinary FLUX generation/refine/reference capabilities. Known editor
classes under other ids are refused before publication; their `image` argument
does not make them ordinary reference pipelines.

The nullable `edit` spec on requests and records contains `source`
(a positive gallery id) and a named frozen recipe such as `kontext-v1`.
`prompt` is the instruction itself, avoiding two competing copies of the
same text. The spec is exclusive with `refine`, mask, outpaint, reference
lists, upscaler and crop anchor. Unknown recipes and incompatible fields
are refused. Do not silently remove an edit in `applied()` and render its
instruction as a normal prompt.

The server resolves the selected checkpoint's recipe and displays the exact
working and output dimensions before Queue. Freeze the source resize rule,
aspect handling, rounding, colour conversion and any crop; record the recipe

with a small supported size and source-aspect mapping; unsupported shapes
get a reason rather than a hidden crop. Stage 0 must settle the exact mapping
against installed code before the schema/preview is implemented.

Keep public checkpoint ids in settings and metadata. Pin model and quantized
artifact revisions in loader recipes, and retain enough recipe identity to
identify the weights used. A different Qwen edition, quantized transformer,

Persist the applied edit spec and instruction in the row and `auradream`
PNG chunk. A nullable `images.edit` migration must update `_COLUMNS`, both

status, not reproduction settings. The saved original source must never be
overwritten or treated as the editor's output.

Give the edit its own canonical CellKey extension from the bound stored
identity: source, recipe and the complete source descriptor, including its
full RGB hash. Resolve and prove that descriptor before expansion, run ids,
Resume/deduplication and More seeds keys; a raw request id/recipe is not a
complete edit identity. Replacing a source's pixels must not reuse an old
edit key, and replay must refuse a mismatch against its frozen proof.
`prompt` already keys the instruction. Preserve seed last and
the existing shape/execution conventions. Compact absent edit data so every

## Lifecycle and interaction

Use the existing explicit Models switch and `main.ensure_loaded()`; there is
one selected checkpoint and no resident second image model. New source edits
use the ordinary load lock, generation gate, revision guard and single worker.
They do not acquire the gate and then await loading. Download denial occurs
before a switch saves/unloads the current model. Failure uses `_load_failure`.

Editor loading keeps the current per-component `PipelineQuantizationConfig`,
`checkpoint_files_released`, candidate publication and teardown rules. Qwen's
processor/vision encoder and every source artifact must be accounted for;
quantizing its denoiser alone is not a host-RAM estimate. No runtime upgrade or
Nunchaku mapping is inferred from a current upstream example.

The backend requires a generator and `callback_on_step_end`, uses `no_grad`,
polls cancellation each step and saves only completed images. First qualify
one image per call; no shared first-generator VAE sample across a batch.
Pause/Skip retain their current call-boundary semantics. Progress labels the
work as an instruction edit; cleanup runs even on cancellation or decode error.

The proposed dialog shows the source, instruction, checkpoint, seed, steps,
supported guidance and server-resolved size. It has no Refine strength slider.
Unsupported/currently unavailable editors give a held reason and a route to
Models, without switching or queuing by themselves. Ordinary composer text is
preserved. The dialog writes its own instruction box with `replaceBoxText`, so
Ctrl+Z works, and never writes the composer; returning focus does not scroll
the page. Source deletion/binning is handled through the existing
`forgetImages` flow. As built, `smoke-instruction-edit.json` covers a stale
preview asked again before Edit queues, a stale revision's 409, keyboard
focus, Ctrl+Z, the 800x900, 1400x700 and 1900x1000 layouts and source/result
inspection (see Stage 2 below).

## Stage 2: backend and dialog, 2026-10-27

**The one gate is the backend instance.** `GenerationBackend.instruction_edit_qualified()`
answers whether this backend may run an edit, and only the literal `True`
opens it (`qualified is True`, so a truthy object stays closed). The base
class answers False. `DiffusersBackend` overrides it with a body that is only
`return False`, and a source scan in `test_instruction_edit_gate.py` holds
every definition under `backend/` to that literal. No setting, environment
variable or flag reads into it. These all ask the same instance:
`require_execution_available` and `require_model_available` (both take
`qualified=`), `edit_unavailable_reason(model_id, qualified=)`, `applied()`,
`check_refine_supported()`, `main.ensure_loaded` and `/api/model/load`. The
diffusers load holds take no `qualified` argument and stay unconditional:
`load`, `_load_prepared`, both editor-class refusals and
`loading.require_custom_pipeline_class`. So even a stand-in that answers True
cannot load the editor on this backend.

The held reasons are five sentences in `instruction_edit.py`.
`INSTRUCTION_EDIT_UNAVAILABLE` covers a closed gate and the Kontext pipeline
class. `INSTRUCTION_EDITOR_UNSUPPORTED` covers Qwen-Image-Edit and the Qwen
editor classes, which have no recipe whatever the gate says.
`_NEEDS_MODEL` covers an open gate with another checkpoint selected; the
selected id is compared exactly, as `bind_request` compares it, so a case
variant needs the editor selected and its load is refused. `_TEXT_TO_IMAGE`
covers Generate on the editor where an edit can queue; with the gate closed
`text_to_image_refusal` gives the gate's own reason instead, never a pointer
at the held dialog. `describe()` sets `text_to_image_reason` from it,
`defaults.text_to_image_reason` carries it, and the page holds Generate and
Run grid with it. `_REPLAY_HELD` covers Generate, Re-render, More seeds and
Finish run of an edit with the gate open. `/api/status` carries
`instruction_edit_supported` and `instruction_edit_reason` from `describe()`,
which overrides the profile.

**The call branch** (`DiffusersBackend._edit_images`) is reached from
`_generate_images_prepared` right after the generator list. It never reaches
the text-to-image kwargs, sigmas or the step that drops unsupported
parameters. Its steps, in order:

1. Require the loaded class to be `FluxKontextPipeline`, with one image, one
   run and one generator.
2. Require every name in `_EDIT_PARAMS` to be in the call's signature. A
   missing name is refused, never dropped.
3. Prove and decode the source through one open handle with
   `instruction_edit_admission.load_bound_source`, then prepare it at the
   recipe's working size.
4. Pass exactly `_EDIT_PARAMS`: the image, the instruction as `prompt`, the
   size with `max_area=w*h` and `_auto_resize=False`, `num_images_per_prompt=1`,
   `max_sequence_length=512`, steps, distilled guidance, the generator and
   the step callback.
5. Call the pipeline under `torch.no_grad()` and `schedule.forced_mu(pipe, None)`.
   The offload hooks are freed and the prepared source is closed in `finally`,
   so cancel and decode errors clean up too.
6. Require exactly one image at the output size. There is no composite.

There is no negative prompt or true CFG, and no strength, mask, latents or
`joint_attention_kwargs`.

**Queueing** has one route, `POST /api/instruction-edit`, which takes an
`InstructionEditSubmission`. It is strict and refuses extra fields: source,
recipe, instruction, width and height from the preview, and optional seed,
steps and guidance. It builds a one-image, one-run request with no negative.
Admission runs in this order:

1. The model-dependent middleware gives 409 for a switch in progress or a
   stale revision.
2. The selected loader and its execution must be runnable.
3. `edit_unavailable_reason` must pass. A refusal is a 422 before any file
   is read.
4. `bind_request` proves the source's pixels, the model and the geometry.
5. The budget and steps checks run, then `jobs.submit`.

The route never asks `refuse_unusable_inputs`, whose text-to-image check
would refuse everything on the editor. Generate, Re-render and More seeds
still never queue an edit: `submission.unusable_input` answers UNAVAILABLE or
REPLAY_HELD after binding. Swap tags, Then refine, grids, Finish and Mass
refine's semantics are unchanged. In `jobs.py`:

- `submit_cells` takes only a bound edit, behind the gate.
- `_run` fails a retained edit job closed whenever the backend is not
  qualified.
- Each edit cell runs `_recheck_edit` as it begins, before `generate`. It asks
  the gate again and proves the source again. A source that is missing, in
  the recycle bin or rewritten since the submit fails that cell in words,
  with no backend call and no row.
- `planned_keys` skips edit cells while the gate is closed, so a gate that
  closes mid-job cannot break other reruns' planning.

**The envelope.** `instruction_edit.QUALIFIED_ENVELOPE` records what stage 3
