# AuraDream UI and UX review

**20 November 2026 · reviewed app revision `d072868f514e`**

The findings below describe the reviewed revision. [Implementation and verification](#implementation-and-verification) records the follow-up.

**Fix the five cases below first.** The everyday path from an author's example to a generated image already works with few decisions. The more consequential problems appear when the user changes course. A checkpoint can be selected while Generate still targets the previous one. An experiment can cost more than its visible estimate. An archive can restore every image while leaving a run impossible to finish. Each has a small, testable interaction change.

The review gives extra weight to Matt's reported use of fixed seeds, Batch and Repeat, comparing results and their sources, selecting across filters, cancelling jobs and archiving the whole gallery. These priorities come from his feature ratings. Browser action counts and layout measurements below are reviewer observations. ## Five changes to make first

### 1. Give an open model picker control over generation

On a 393 × 852 touch viewport, start on Animagine, type a prompt, open Models and choose FLUX.1 Krea. **Switch & load** and **Generate** are simultaneously visible as purple primary buttons. Tapping Generate closed the picker and saved an image made by Animagine. The picker accurately says “Unsaved changes” and names the loaded model. The competing button still lets the user act on the opposite choice in one tap. [Portrait screenshot](review-2026-11-20-ui/models-portrait.png) · [Phone dock](../../web/styles/phone.css#L177) · [Generate handler](../../web/generation.js)

The desktop has a second route to the same outcome. Restore a nonempty draft on a cold load with no saved checkpoint and no Hugging Face sign-in, so the app opens its automatic Models suggestion. Animagine is checked, focus remains on the page body, and one native Ctrl+Enter loads FLUX.1 Krea and stores a result under that checkpoint on the fake. This reproduced twice. A real load depends on access and cache state. [Automatic picker](../../web/model-switch.js#L946) · [Shortcut dispatch](../../web/app.js#L797)

Rotation makes choosing deliberately harder. At 740 × 360 with the unsaved selection and download notice, the sticky footer left **1 CSS pixel** for the checkpoint list. Swiping through 726 pixels of list content still exposed no tappable radio center. At 852 × 393 the available strip measured 27 pixels. [Landscape screenshot](review-2026-11-20-ui/models-landscape.png) · [Sheet footer](../../web/styles/phone-sheets.css#L160)

**Acceptance.** Opening Models gives the picker ownership of Generate and Ctrl+Enter, including when focus began on the page body. A short landscape phone can reach and read the selected checkpoint and its actions. Applying or dismissing returns to the draft, where the ordinary Generate shortcut works again.

### 2. Explain the loss of unfinished work before Bundle & clear

Start with a two-cell grid that saved one image and can still **Finish** the missing cell. In Bundles, choose Entire gallery, type the correct count, use **Bundle & clear gallery**, then import that exact verified archive. In the repeated case all four gallery records returned. The interrupted run recovered its saved image and zero planned cells. **Finish run** was held, and the explanation attributed this newly created run to an older app version. The confirmation had enumerated images, checkpoints and bin contents without identifying the outstanding work. [Confirmation screenshot](review-2026-11-20-ui/archive-confirmation.png) · [Confirmation wording](../../web/index.html#L2340) · [Archive construction](../../backend/bundles.py#L541) · [Finish explanation](../../backend/api_runs.py#L183)

**Acceptance.** With an affected run, the confirmation explains that its images will restore and its remaining work will lose the Finish action. Give the user a direct way to review unfinished runs before clearing. An imported run lacking a plan gets an accurate explanation. This works with the project's existing image-bundle format. [Continuation and bundle design](plan-continue-run.md)

### 3. Make the visible grid count agree with the submitted job

On an idle FLUX.1 Krea fake, enter a plain prompt, wait for a one-seed preview, change Seeds to 6, then immediately press Ctrl+Enter in that field. At the actual Run grid click and POST, the page still showed **1 image · 1 seed**. Six images were made. The reverse test showed **6 images · 6 seeds** and made two. The time and disk estimates also belonged to the previous preview. Both cases used native input with ordinary local response times. The preview waits 250 ms after editing, while submission reads the current form immediately. [Submission](../../web/grid-preview.js#L82) · [Preview scheduling](../../web/grid-preview.js#L405)

**Acceptance.** A change immediately invalidates the displayed totals. If the user presses Run grid during recalculation, the reviewed count and settings must agree with the job they authorize. Keep one-press submission for a current preview. Exercise a count increase and decrease, with both the button and keyboard shortcut.

### 4. Keep a failed attempt distinguishable from the previous result

Generate a successful 1024-square image with seed 522. Change the prompt and seed to 523 and submit a fixture that fails before producing a preview. At 1366 × 768 the previous image, its seed and **More seeds** still occupied the viewer. The detailed failure began at y=807. The tab title correctly said “Nothing made,” but someone looking at the image had little reason to inspect the tab or scroll. Following More seeds would continue the previous result. [Screenshot after failure](review-2026-11-20-ui/failed-after-success.png) · [Stream handling](../../web/job-stream.js#L85) · [Outcome handling](../../web/job-results.js#L199)

**Acceptance.** Keep the last good image available and label it in place when a newer submission produces none. A message such as “No image was made. Showing previous result #9” can lead to the existing error and recovery controls. Verify a failed first image, a failed attempt after success, and a partially successful batch.

### 5. Keep the Assistant's reply visible and its keyboard focus usable

At 480 × 360 with a fine pointer, a returned two-draft answer said **“Choose a draft”** while the conversation area measured **0 pixels high**. It contained several hundred pixels of text. The same answer had 330 pixels of conversation space at 1280 × 720. At 640 × 450, tabbing from the Assistant eventually focused Examples, Check, Reset, the prompt and Generate behind the panel. Hit-testing those control centers reached the Assistant covering them. Phone-specific background focus protection depends on the input-device classification. [Small-window screenshot](review-2026-11-20-ui/assistant-small-window.png) · [Sidebar sizing](../../web/styles/prompt-assistant.css#L3) · [Background focus handling](../../web/assistant-phone.js#L31)

**Acceptance.** At a short desktop or zoom-equivalent viewport, the user can read, reach and apply a returned draft. When the panel covers the workspace, Tab and Shift+Tab stay among visible controls, and Escape returns to the opener. At a wide viewport the user retains access to genuinely visible side-by-side controls.

## Visual hierarchy and task trials

On desktop, the single purple Generate button anchors the settings column, and the gallery gives most of its space to the images. With an existing gallery, the idle viewer collapses to one line. This made browsing immediate at 1400 × 900. On a phone, Create and Gallery provide recognisable destinations. The tested route from typing a prompt through Check, Generate and opening the result worked using touch input. Preserve direct Generate, the image-first gallery and the source inspector. The failures above happen where two controls compete, a visible image belongs to earlier work, or a selection summary is separated from the action that consumes it.

The strongest successful feedback was specific. A grounded prompt Check kept its source, prompt comparison previewed **8 images · 2 versions × 4 seeds**, and Outpaint showed a 1024-square source becoming 1280 square with 128 pixels added on each side. Reuse restored the inspected prompt and seed and offered Undo. When a job was cancelled after one completed image, that image survived and recovery identified the remaining work. These are good patterns for the grid total, edit provenance and archive receipt.

Thumbnail sizing is a separate layout trade-off worth testing. At 2560 × 1305 the gallery exposed S/M and Fit/Crop directly. At 1400 × 900 it exposed neither. The wide-screen breakpoint is deliberate, and Matt rated the combined task of adjusting card size or Fit/Crop as frequent. Try a compact Gallery view control on desktop below 1800 pixels and measure whether adjusting the crop while inspecting a portrait gets easier. A comparable public design puts these same two choices in one gallery settings menu. [Gallery controls](../design-notes.md#the-gallerys-cards) · [Reported gallery use](../design/preferences.md#e---finding-and-organising-images) · [InvokeAI gallery settings](https://v7.invoke.ai/users-guide/gallery/gallery-reference/#gallery-settings)

Two design questions deserve Matt's existing **DEV#1** trial before a broader rearrangement.

1. **Can you predict and inspect the scope of a bulk action?** Pick across two filters, return to a third, name the affected images and remove one while keeping the draft. Compare today's count with a minimal picked-image review. Time only interaction, record mistaken predictions, and keep the ordinary mouse and keyboard shortcuts available.
2. **Can you move between making and judging with your place intact?** Start with a fixed seed and an unfinished draft, compare a result to its source, return to that draft, then make more seeds of the intended image. Record detours and any point where the user must reconstruct a filter or source. InvokeAI's documented gallery keeps comparison and selective settings reuse close to the image. AuraDream already has those operations. The trial can test the particular handoff that failed here. [InvokeAI gallery reference](https://v7.invoke.ai/users-guide/gallery/gallery-reference/) · [Existing trial protocol](../design/validation.md)

One additional task would extend the eight-card baseline. Compose a guided tag prompt, introduce one prompt variable, cross it with a small Steps or CFG sweep, predict the work, then run it. Also reconcile the optional trial rubric before scoring it. Matt rated Then refine and saved searches **Sometimes** on November 3. Saved setups remains unrated.
