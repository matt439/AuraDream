# Focused generation workflow review — 2026-10-26

The scope is Matt's reported everyday usability friction: setup, job states,
results, reuse, action discovery and recovery. This is a bounded actual-browser
review, not a redesign or a new feature list. The in-app browser uses an isolated
fake gallery on port 9920; its initial viewport is 1275x712. No real model or
GPU work, model download, push or deployment is involved.

## P1: mixed prompt prose is presented as invalid tags (`PA#10`)

Matt's exact example is `1boy, masterpiece, a man wearing a red, old hat`.
The repository's Kohaku profile explicitly enables `hybrid_prompt`. Selecting
that profile with Apply & save and pasting the example reproduces the report:
the prompt readout says **4 prompt tags: 2 known, 2 unknown**. The tray shows
both `a man wearing a red` and `old hat` as red tag chips, with drag/edit/delete
controls. The raw prompt is unchanged. This is a representation defect, not
only a colour problem.

The two recognized tags should retain annotations; the natural-language
portion should stay one ordinary text block, preserving its internal comma.
Dictionary absence alone does not prove text in a mixed prompt is a malformed
tag. Concrete known-tag problems and explicit tag-only paths must remain
available. Contextual grouping must not leak through lexical caches or split
prose during an explicit tag edit or reorder.

Built and qualified: the server supplies exact contextual tag/prose spans
only for explicitly hybrid guides, separately from unchanged dictionary
verdicts. The tray now shows two annotated tags and the single selectable
text passage `a man wearing a red, old hat`, with no tag tools on that text.
Raw prompt text and its commas stay unchanged. Refine uses the same context,
and Check/critic withhold only reorders that would split a prose passage.
CPU and browser cases cover pure tags/prose, punctuation, known titles,
multiple passages, model switches, cached/delayed replies and editing/Undo.
Independent backend and frontend reviews are clear.

## P2: malformed number input silently becomes a default (`GEN#24`)

Actual browser typing `1e` into Steps leaves the native input displaying `1e`
while its DOM value is empty and `validity.badInput` is true. Generate still
starts a job. The resulting fake image's large-view Sampling row says **28
steps · CFG 5 · no Mu**: the invalid entry was silently treated as an intentional
blank and replaced by the checkpoint default.

Malformed numeric input should refuse submission with a readable field name
and focus on the field. Deliberate blanks must keep their established meanings
(profile Steps/CFG, random Seed); controls that do not apply must stay ignored.
Saved reruns and More seeds must not acquire unrelated composer validation.

Built and qualified: Generate, Run grid and comparison now reject native
`badInput` with the field name and focus, before a POST. Intentional blanks,
disabled controls and sampling values overridden by axes retain their
established behavior. The native-typing browser regression passes; independent
review is clear. Saved reruns and More seeds remain independent of the composer.

## P2: a fast queued failure can lose its outcome (`GEN#25`)

The same browser queued two one-image jobs behind a paused two-image job:
`a harbour at dawn`, then `a lighthouse [fail]`. After Resume, the failing
job finished immediately after the harbour. The server's finished-job listing
records zero images and `1 image failed and was skipped`; the page instead
keeps the preceding harbour's **Finished 1 image** line with no failure or
recovery action for the final accepted job. The queue adopter asks only for
currently active jobs, so a terminal outcome can fall between watches.

Accepted jobs owned by this tab need their terminal outcomes reconciled once,
without replaying old jobs, taking another tab's completed work or replacing
foreign-job viewer behavior.

Built and qualified: unseen accepted receipts survive queue resync. A bounded
history lookup finds outcomes missed by the active listing, and ordinary
stream/finish handling settles them once in receipt order with recovery
actions. Transient failures retry; historical ownership after reload, foreign
completed jobs and explicitly cancelled/forgotten rows do not authorize replay.
The isolated race regression and independent review are clear.
